# Working Log

## 2026-05-31

- Started implementation from the partitioned poller working plan.
- First slice extracts shared public contracts and a thin runner lifecycle base before adding partitioned scheduler state.
- Decision: move linked cancellation and tick serialization into `PollRRunnerBase` so both poller families can share the same lifecycle without forcing shared cursor or scheduling logic.
- Decision: simplify `PollRContext` into subscriber/cursor state only; runner lifetime now belongs to the new base class.
- Added direct-only partitioned poller types: `PartitionFeedState`, `PartitionedPollRContext`, `PartitionedPollRBase`, and `PartitionedPollRCaster`.
- Decision: keep direct subscriber intake global and use one `_stateLock` in `PartitionedPollRContext` for partition creation, scan-order mutation, and idle removal.
- Decision: defer projection support until the direct scheduler and delivery behavior validate cleanly.
- Added partition-aware registered projection support in `PartitionProjectionModels.cs`.
- Reasoning: partition-local catch-up and idle-removal accounting were clearer in a parallel implementation than by widening the existing shared-feed projection registry.
- Updated the ASP.NET SSE adapter to target the shared subscriber/projection contracts so both poller families can reuse the same HTTP builder surface.
- Added coverage for direct partition scheduling, partition-local projection behavior, and shared HTTP adapter support for `PartitionedPollRCaster`.
- Validation: `dotnet run --project src/PollR.Tests --disable-logo` now passes with 47 tests.
